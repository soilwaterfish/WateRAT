What happens from local data to a reviewable result

Start with one small AOI and walk it through the same stages that the full state pipeline uses. The only difference at state scale is that targets executes and caches each stage for you.

1. Prepare dataPlace source files locally and choose an AOI.
2. Filter PODsApply state rules and the shared schema.
3. Link COMIDsIntersect PODs with local NHDPlus catchments.
4. Route and reviewAccumulate allocations and write a GeoPackage.

Try the workflow on a small AOI first

These are the core steps from the small-scale walkthrough. They make the input, filtering, and routing decisions inspectable before you run every state.

1. Load an AOI and inspect the supplied example

library(WaterRAT)

fixture <- system.file("extdata", "pod_example_basins.gpkg", package = "WaterRAT")
example_basins <- sf::read_sf(fixture, layer = "pod_example_basins")

mt_aoi <- dplyr::filter(example_basins, state_code == "MT")
id_aoi <- dplyr::filter(example_basins, state_code == "ID")

The package fixture provides one small Montana basin and one small Idaho basin. Replace either geometry with your own basin, state boundary, or project AOI.

2. Read only the relevant local records

mt_pods <- get_mtwr(
  filter_geom = mt_aoi,
  layer = "WRQS_PODS",
  local_path = "data/WRQS_Dataset_GDB.gdb"
) |>
  date_cleaning()

id_rights <- get_idwr_pods(
  local_path = "data/idwr.gdb",
  filter_geom = id_aoi
) |>
  expand_idwr_pods_by_use() |>
  standardize_idwr_water_rights() |>
  filter_water_rights_month(month = 8)

Montana applies active, surface-water, non-missing-flow, and purpose filters. Idaho is filtered before report pages are scraped; its Water Uses and August rates are then standardized.

3. Connect PODs to the routing network

network <- read_nhdplus_flowlines(
  path = "data/NHDPlusV21_National_Seamless_Flattened_Lower48.gdb",
  filter_geom = example_basins,
  layer = "NHDFlowline_Network"
)

mt_candidates <- standardize_mt_pod_candidates(mt_pods)
mt_comid_index <- index_water_right_comids(
  mt_candidates,
  catchments = read_nhdplus_catchments(
    path = "data/NHDPlusNationalData/NHDPlusV21_National_Seamless_Flattened_Lower48.gdb",
    filter_geom = example_basins
  ),
  cache_path = "data/mt_pod_example_comids.rds",
  workers = 1,
  throttle_seconds = 0.5
)

mt_rights <- select_mt_downstream_pods(mt_pods, mt_comid_index, network) |>
  standardize_mt_water_rights()

For Montana, repeated WRKEY PODs are represented by the furthest-downstream candidate: the lowest NHDPlus hydroseq. The selected COMID and method remain in the output as audit fields.

Prep once; reroute when needed

Preparation and network analysis intentionally use different targets scripts and stores. The preparation script filters each supported state, reuses stable Idaho report scrapes, selects Montana’s downstream-most POD per WRKEY, assigns COMIDs, intersects Forest Service ownership, and upserts state rows into one reusable GeoPackage. The final prep target is the sole owner of that GeoPackage, so a Montana update does not invalidate completed Idaho preparation. The analysis script reads only that prepared layer.

# Refresh the Idaho and Montana preparation cache. This uses prep_targets.R and its own
# _targets_prep store, leaving the routing pipeline’s _targets store intact.
targets::tar_make(script = "prep_targets.R", store = "_targets_prep")

# Review the prepared GeoPackage, then route every state it contains together.
targets::tar_make()

# Or refresh Idaho directly outside targets:
refresh <- refresh_idwr_network_water_rights(
  local_path = "data/idwr.gdb",
  filter_geom = idaho_boundary,
  fs_boundary = idaho_fs_boundary,
  nldi_cache_path = "data/cache/nldi/id.rds",
  cache_path = "data/cache/prepped/water_rights.gpkg",
  workers = 1,
  throttle_seconds = 0.5
)
refresh$changes

On a later Idaho update, unchanged POD identity, report URL, status, source, and location reuse their cached Water Uses rows; only new or changed POD reports are scraped. Both states assign COMIDs by local catchment intersection. NLDI checkpoints under data/cache/nldi/ are used only when a POD has no single local catchment match. Use force_rescrape = TRUE when IDWR has corrected report content without changing the source-layer identity.
