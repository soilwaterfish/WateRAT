How Montana and Idaho become comparable

Each state keeps its authoritative identifiers and reported values. The adapter only renames, filters, parses, or explicitly derives fields; it does not silently invent a conversion.

Montana

Filter, then make one site record

WRQS_PODS → eligibility filter → August-period filter → downstream selection → canonical record

Active surface-water PODs with a reported flow are reduced to records whose PERIOD_OF_DIVERSIONS overlaps August. WR_NUMBER identifies the right; when one WRKEY has several PODs, the lowest NHDPlus hydroseq identifies the downstream canonical site.

Idaho

Filter, then make one site record

PODRight → eligibility filter → scrape and expand uses → August-period filter → canonical record

Active eligible PODs are scraped only after source and location filtering. WaterRightNumber identifies the right and PointOfDiversionID identifies the site; qualifying August Water Uses rows are averaged back to one canonical POD site.

Comparable does not mean identical. Both adapters return the same canonical columns and point geometry. State-specific provenance remains available in the source data or, for Idaho, in audit fields such as idwr_uses, condition_codes, and condition_text.

Derived review fields

Network preparation may add comid, nldi_error, and fs_intersection. They are audit fields derived after canonical validation; they are not requirements for a new state adapter.

Do not invent conversions. A rate reported in an unsupported unit remains missing from max_flow_cfs until a documented conversion is implemented.
